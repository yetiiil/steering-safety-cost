# Could Inference-Time Interventions Preserve Alignment?<br>Safety Cost of Steering Vectors Is Separable and Reducible

**Yuxiao Li, Gjergji Kasneci**  
Technical University of Munich · Munich Center for Machine Learning

**COLM 2026** · [Paper](https://arxiv.org/abs/2608.08383) · [Data Card](DATA_CARD.md)

Official implementation of **CAST — Constrained Ablation for Safe STeering**.
This repository provides the method, fixed inputs for the main experiments,
and training and evaluation runners for Llama-3.1-8B-Instruct,
Qwen2.5-7B-Instruct, and Qwen2.5-14B-Instruct.

## Overview

Activation steering changes a model's behavior by adding a vector to its residual
stream. Such interventions can also weaken refusal behavior. CAST learns a
subspace to remove from an existing steering vector, reducing its safety cost
while preserving the intended behavioral effect and controlling false refusals.
The model weights remain frozen.

For a unit direction r̂ and steering vector v, CAST computes:

```text
ṽ  = v − r̂ r̂ᵀ v
v* = ṽ · ‖v‖ / ‖ṽ‖
```

The direction is learned through constrained optimization:

```text
minimize  L_safety
subject to  L_effect ≤ ε_e,  L_frr ≤ ε_f
```

The default configuration uses rank 1. The learned direction and the resulting
steering vector are saved separately, so the vector can be used directly at
inference time.

## Installation

Use separate environments for training and evaluation. Training uses Python 3.10;
evaluation supports Python 3.10 or newer.

```bash
python3.10 -m venv .venv-train
.venv-train/bin/pip install -r requirements-train.txt

python3.11 -m venv .venv-eval
.venv-eval/bin/pip install -r requirements-eval.txt
```

| Environment | Main dependencies | Used for |
| --- | --- | --- |
| Training | PyTorch 2.5.1, Transformers 4.47.0, NNsight 0.3.7 | DIM extraction and CAST training |
| Evaluation | steering-vectors 0.12.2, PyTorch ≥2.6, Transformers ≥4.51 and <5 | CAA extraction, generation, and scoring |

Keep the dependency constraints in the requirement files. The two environments
use different Transformers versions to support their respective libraries.

### Credentials

Copy `.env.example` to `.env` and configure the credentials needed for your run:

```bash
cp .env.example .env
```

| Variable | Purpose |
| --- | --- |
| `HF_TOKEN` | Access to gated model and judge weights |
| `OPENAI_API_KEY` | GPT-based behavior and false-refusal scoring |
| `WANDB_MODE` | Set to `disabled` to train without Weights & Biases |

Python entry points load `.env`. When using the shell runners, also export the
required variables in your shell; `scripts/09_judge.sh` checks `OPENAI_API_KEY`
before launching GPT scoring. Leave `SAVE_DIR` unset or empty for the default
artifact layout; use an absolute path when overriding it.

## Obtaining data and artifacts

The fixed input package is included in
[`data/paper/inputs.zip`](data/paper/inputs.zip). Restore it offline from the
repository root:

```bash
python scripts/00_download_data.py
```

This restores 26 files covering CAST and DIM training data, the three main
behavior datasets, benign prompts, JailbreakBench, and recorded attack inputs.
The archive and restored files are verified against
[`data/paper/manifest.json`](data/paper/manifest.json), which records counts,
SHA-256 hashes, provenance, and preprocessing. Model weights are obtained
separately; steering vectors and model responses are generated by the pipeline.

Use `--list` to inspect available input groups or `--only train` to restore a
specific group. Existing matching files are reused. Use `--force` to replace
modified inputs with the packaged versions. See [DATA_CARD.md](DATA_CARD.md)
for dataset details and terms.

## Quick start: Qwen2.5-7B

The following example trains and evaluates CAST for
`power-seeking-inclination`. Run these commands from the repository root.

### 1. Extract and normalize the CAA vector

```bash
source .venv-eval/bin/activate
export MODEL_FAMILY=qwen
export MODEL_SIZE=7b
export BEHAVIORS=power-seeking-inclination

python scripts/00_download_data.py
bash scripts/01_generate_vectors.sh
bash scripts/02_normalize_vectors.sh
```

Normalization uses the per-model, per-layer target norms in
[`configs/normalization_target_norms.yaml`](configs/normalization_target_norms.yaml),
keeping the steering scale consistent across behaviors.

### 2. Extract DIM metadata and train CAST

```bash
source .venv-train/bin/activate
bash scripts/03_extract_dim_direction.sh
bash scripts/05_train_cast.sh --no_wandb
```

The model, behavior, and layer settings are inherited from the exported variables
above. Training reads the corresponding model configuration in `configs/`.
For this example, the learned artifacts are saved under:

```text
artifacts/cast_vectors/qwen2.5-7b-instruct/dim_1_masked_kl/
├── final_vector_power-seeking-inclination_qwen2.5-7b-instruct_masked_kl.pt
└── sanitized_power-seeking-inclination_qwen2.5-7b-instruct_masked_kl.pt
```

`final_vector_*.pt` contains the learned basis; `sanitized_*.pt` is the steering
vector to use for inference. Training one Qwen2.5-7B CAST vector takes approximately
90 minutes on an A100 80 GB with the default settings.

### 3. Evaluate safety and behavior at α = 1

```bash
source .venv-eval/bin/activate

MULTIPLIERS="0 1" CAST_MULTIPLIERS="1" \
    bash scripts/06_run_steering.sh

EFFECT_MULTIPLIERS="0 1" CAST_EFFECT_MULTIPLIERS="1" \
    RUN_OPEN_ENDED=0 bash scripts/08_run_open_ended.sh

EVALUATORS=strongreject_finetuned bash scripts/09_judge.sh
```

This compares the unsteered model, the original CAA vector, and CAST across the
seven attack scenarios, and computes MCQ behavior matching. StrongREJECT scoring
runs locally; MCQ matching does not require a GPT judge.

For open-ended behavior evaluation and false-refusal evaluation, generate the
corresponding responses and score them with the paper's GPT judge:

```bash
EFFECT_MULTIPLIERS="0 1" CAST_EFFECT_MULTIPLIERS="1" \
    RUN_AB=0 bash scripts/08_run_open_ended.sh
EFFECT_MULTIPLIERS="0 1" CAST_EFFECT_MULTIPLIERS="1" \
    bash scripts/07_run_benign.sh

# Requires OPENAI_API_KEY exported in the shell.
EVALUATORS="gpt_behavior_scorer gpt_false_refusal" bash scripts/09_judge.sh
```

The defaults in `scripts/config.sh` run the broader multiplier sweeps. Adjust
`BATCH_SIZE` and `BATCH_SIZE_LONG_PROMPT` to fit the available GPU memory.

## Models and experiment settings

| Model | `MODEL_FAMILY` | `MODEL_SIZE` | Steering layer | Configuration |
| --- | --- | --- | ---: | --- |
| Llama-3.1-8B-Instruct | `llama` | `8b` | 13 | [llama-3.1-8b-instruct.yaml](configs/llama-3.1-8b-instruct.yaml) |
| Qwen2.5-7B-Instruct | `qwen` | `7b` | 18 | [qwen2.5-7b-instruct.yaml](configs/qwen2.5-7b-instruct.yaml) |
| Qwen2.5-14B-Instruct | `qwen` | `14b` | 30 | [qwen2.5-14b-instruct.yaml](configs/qwen2.5-14b-instruct.yaml) |

The main behaviors are `corrigible-more-HHH`, `power-seeking-inclination`, and
`self-awareness-good-text-model`. Set `BEHAVIORS` to a space-separated list to
run several behaviors. Without an override, the stage scripts run all three.

The YAML files specify model-specific training settings, including the steering
layer, training multipliers, constraint tolerances, and initial dual variables.
The complete refusal-token sets used by the implementation are defined in
[`cast/divergence.py`](cast/divergence.py). Training applies steering to prompt
and generated positions and masks padding and positions after EOS in the losses.

All stage runners share [`scripts/config.sh`](scripts/config.sh). Its defaults
use evaluation multipliers `-1.5 -1 -0.5 0 0.5 1 1.5` for attack evaluation and
`-1 0 1` for behavior and false-refusal evaluation. Multiplier 0 provides the
unsteered reference. CAST evaluations reuse that reference.

## Evaluation and outputs

| Evaluation | Generate | Score |
| --- | --- | --- |
| Jailbreak safety | `scripts/06_run_steering.sh` | StrongREJECT |
| False refusals on benign prompts | `scripts/07_run_benign.sh` | GPT false-refusal judge |
| MCQ and open-ended behavior | `scripts/08_run_open_ended.sh` | MCQ matching / GPT behavior judge |
| General capability | `scripts/10_run_utility.sh` | Benchmark-specific accuracy |

Attack evaluation covers `none`, `prefix`, `refusal_suppression`, `aim`, `gcg`,
`autodan`, and `pair`. Recorded AutoDAN, PAIR, and GCG inputs are restored from
the package; the remaining scenarios use templates in `run_steering.py`.

The scoring conventions are:

- **ASR:** mean continuous StrongREJECT score × 100. The auxiliary binary label
  at score ≥0.25 is separate from the reported ASR metric.
- **False-refusal rate:** mean of full-compliance (0), partial-refusal (0.5), and
  full-refusal (1) scores; unclassified responses are counted separately.
- **Behavior score:** a 0–10 score on open-ended completions using the supplied
  behavior rubric. MCQ matching is reported separately.
- **GPT judge:** `gpt-4o`, with temperature 0, for both GPT-based metrics.

Decoding is greedy, with up to 300 new tokens for attack and benign prompts and
100 for open-ended behavior prompts. StrongREJECT receives the first 512 response
characters. Numerical results can vary with hardware and dependency versions.

Outputs are written to `jailbreak_results/`, `benign_results/`, `results/`, and
`utility/`. Scored files are saved in sibling directories named
`<behavior>_<judge>_evaluation/`. Filename prefixes identify the condition:
`results_` for CAA or the multiplier-0 reference, and `results_single_` for CAST.
The scoring runner reuses existing evaluation files; pass `--overwrite` to rescore.

For IFEval, install the NLTK resource once in the evaluation environment:

```bash
python -c "import nltk; nltk.download('punkt')"
```
